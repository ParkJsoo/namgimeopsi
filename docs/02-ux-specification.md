# UX specification

## Experience loop

```text
장보기 후 기록 → 냉장고 상태 파악 → 오늘의 한 끼 결정 → 소비 처리 → 더 정확한 다음 추천
```

홈은 재고 목록이 아니라 사용자가 오늘 행동할 이유를 보여 주는 화면이다. 재고 목록은 확인·수정이 필요한 보조 화면으로 둔다.

## Information architecture

```text
홈
├─ 오늘 먼저 먹을 것
├─ 오늘의 메뉴
└─ 빠른 추가

냉장고
├─ 냉장 / 냉동 / 실온
├─ 먼저 먹기 정렬
└─ 재고 상세·수정

나
├─ 기본 보유 재료
├─ 알림 설정
└─ 가구 인원·조리 선호
```

중앙 플로팅 버튼의 추가 방식은 세 가지로 제한한다.

- 영수증으로 등록
- 남은 음식 등록
- 직접 추가

## Core flow 1 — Receipt to inventory

```text
홈의 장 본 것 등록
→ 영수증 촬영 또는 사진 선택
→ AI 분석 상태
→ 인식 결과 검수
→ 재고 반영 완료
```

### Screen behavior

- 분석 중에는 `상품명을 식재료로 정리하고 있어요`라는 단계형 진행 문구를 보여 준다.
- 검수 화면은 `확인됨`과 `확인 필요` 그룹으로 나눈다.
- 항목은 표준 재료명, 수량, 보관 위치, 날짜를 한 줄에서 빠르게 수정할 수 있다.
- AI가 읽은 원문은 펼쳐 보기에서 확인할 수 있다.
- 사용자는 스와이프 또는 제외 버튼으로 잘못 읽힌 항목을 제거한다.
- 재고 반영 완료 뒤에는 새로 입고한 재료 중 먼저 사용할 항목을 보여 주고 홈으로 연결한다.

## Core flow 2 — Leftover registration

```text
빠른 추가
→ 남은 음식 선택
→ 사진 또는 이름 입력
→ 인분·보관 위치 확인
→ 저장
```

### Defaults

| 필드 | 기본값 |
| --- | --- |
| 보관 시작일 | 지금 |
| 보관 위치 | 냉장 |
| 양 | 1인분 |
| 날짜 표현 | 권장 섭취 시점 |

예시 문구: `남은 마라탕 · 냉장 보관 시작 오늘 · 내일까지 드시는 걸 권장해요.`

## Core flow 3 — Decide, cook, and consume

```text
홈의 오늘 먼저 먹을 것
→ 메뉴 카드 세 개
→ 레시피 상세 또는 그냥 먹기
→ 조리/섭취 완료
→ 재료 차감 확인
→ 홈과 재고 갱신
```

메뉴 카드는 다음 정보를 반드시 보여 준다.

- 15분 등 예상 조리 시간
- 1인분 또는 2인분
- 보유 재료 충족도와 부족 재료
- `애호박과 두부를 오늘 안에 쓰기 좋아요` 같은 추천 이유

## Key screens

| 화면 | 목적 | 핵심 요소 |
| --- | --- | --- |
| 온보딩 | 문제와 약속 전달 | 가구 인원, 조리 빈도, 기본 보유 양념 |
| 홈 | 매일 열 이유 제공 | 오늘 먼저 먹을 것, 메뉴 세 개, 빠른 추가 |
| 빠른 추가 | 입력 방식 선택 | 영수증, 남은 음식, 직접 추가 |
| 영수증 촬영 | 높은 품질의 입력 획득 | 촬영 가이드, 갤러리, 재촬영 |
| AI 분석 | 대기 시간 설명 | 단계형 로딩, 실패 시 수동 입력 |
| 검수 | AI 결과 통제 | 확인됨/확인 필요, 인라인 수정, 제외 |
| 입고 완료 | 성취감과 다음 행동 | 입고 수량, 먼저 먹을 재료 CTA |
| 남은 음식 등록 | 배달·반찬 기록 마찰 최소화 | 이름·사진, 양 칩, 위치, 권장 섭취 시점 |
| 냉장고 | 재고 확인과 정정 | 보관 위치 필터, 임박 정렬, 상세 수정 |
| 메뉴·레시피 | 저녁 결정 | 추천 근거, 부족 재료, 조리 단계 |
| 완료·차감 | 재고 최신성 유지 | 재료 체크, 단위 수정, 다 먹음/남김/폐기 |

## Trust and safety rules

1. AI는 초안을 만들지만 자동 저장하지 않는다.
2. 낮은 확신도에는 `AI 추정`과 `확인 필요` 상태를 명시한다.
3. `포장 소비기한`, `구매일`, `개봉일`, `조리·보관 시작일`, `권장 섭취 시점`을 혼용하지 않는다.
4. 조리 음식과 잔반의 권장 섭취 시점은 식품 안전 보증이 아니며 사용자가 수정할 수 있다.
5. 알림은 `메뉴 보기 / 먹었어요 / 아직 있어요`처럼 바로 행동할 수 있어야 한다.
