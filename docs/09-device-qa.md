# 실기기 QA 기록

## Galaxy 키보드 회피 수정 및 스크롤 확인 (2026-09-08)

- SM-F766N / Android 16에서 최신 로컬 Debug 빌드·설치에 성공했다. 테스트 영수증은 사용자가 기기에 저장했다고 확인했다.
- 남은 음식 등록 시 사용자가 본체에서 입력칸/버튼이 키보드에 가려지고 스크롤도 되지 않는다고 보고했다. 직접 캡처로 확인한 결과와 구분한다.
- 공용 `KeyboardSheet`의 Android `behavior`가 미지정이었던 것을 `height`로 변경했다. 키보드가 차지하는 높이에 맞춰 스크롤 영역을 줄이도록 했으며 iOS의 `padding`은 유지한다.
- `height`만 적용한 뒤 사용자가 버튼 끝만 보이고 스크롤하면 키보드가 닫힌다고 보고했다. 전문 에이전트가 설치된 React Native의 Android ScrollView 구현에서 `on-drag`가 `dismissKeyboard()`를 호출하는 것을 확인했다. Android에만 `keyboardDismissMode="none"`을 적용했고 iOS 동작과 버튼의 `keyboardShouldPersistTaps="handled"`는 유지했다.
- 수정 후 연결된 갤럭시에서 ADB 터치 스와이프와 화면 캡처로 한글 키보드가 열린 채 마지막 권장 시점·`냉장고에 담기`·`닫기` 전체가 보이는 것을 직접 확인했다. 기존 `카레`·`2인분` 값도 유지됐다. 이번에는 저장을 누르지 않았으며 이후 시스템 뒤로가기로 시트가 닫혀 홈으로 복귀했다.
- TypeScript·lint·diff 검사 통과. 사용자도 본체에서 스크롤이 잘 되고 끝까지 내리면 버튼이 잘 보인다고 재확인했다. 남은 음식 시트의 키보드 유지 스크롤·하단 버튼 접근은 통과로 기록한다. 영수증·조리 완료 시트의 후속 확인은 아래에 기록한다. 키보드 재열기 반복은 별도 확인이 남아 있다. 캡처는 임시 파일로만 확인했으며 저장소에 추가하지 않았다.

## 환경과 범위

- 코드 기준: `d960a6c` (`fix: allow cancelling inventory editor on iOS`)
- iPhone 13 mini / iOS 26.6 / USB 설치한 로컬 Debug 앱, Mac의 iPhone 미러링으로 조작
- 갤럭시 SM-F766N / Android 16 / 로컬 Debug 앱 설치·실행 확인까지 완료
- 앱 ID: `com.parkjsoo.namgimeopsi`. Metro가 필요한 Debug 실행이며 preview build 검증은 아니다.
- 입력 이미지: `~/Downloads/namgimeopsi-test-receipt.png`를 사용자가 iPhone 사진 앱에 저장했다. 개인정보 없는 테스트 영수증이며, 현재 분석 결과는 이미지 내용과 무관한 고정 fixture다.
- 아래 시각 결과는 이 세션의 미러링 캡처로 확인했다. 별도 증거 이미지 파일이나 영상은 저장하지 않았다. 원격 DB/RPC를 직접 조회하는 E2E는 이번에 재실행하지 않았다.

## Galaxy 영수증 검수 — 사용자 본체 확인 (2026-09-08)

- 사용자가 `+ → 영수증으로 등록`에서 저장된 테스트 영수증을 선택하고 검수 화면에 진입했다.
- 품목 이름 입력으로 키보드를 연 뒤 끝까지 스크롤해 `6개 냉장고에 담기`·`아직 저장하지 않을게요` 버튼이 보이는 것을 확인했다고 보고했다. 영수증 검수의 키보드 스크롤·하단 버튼 접근은 통과다.
- 이번 확인은 사용자 본체 보고이며 별도 캡처는 없다. 입고 확정, 권한 거부/제한 상태, 원격 저장 검증까지 완료했다는 의미는 아니다. 조리 완료 시트 후속 결과는 아래에 기록한다.

## Galaxy 조리 완료 — 사용자 본체 확인 (2026-09-08)

- 사용자가 영수증 검수를 취소하고 홈의 애호박 두부덮밥을 선택한 뒤, 두부의 `남은 양`에 `반 모`를 입력하는 안내를 수행했다고 보고했다.
- 키보드를 연 채 스크롤해 `재료 사용 완료`·`아직 있어요` 버튼이 모두 보이는 것을 확인했다. 사용자 본체 보고 기준으로 조리 시트의 입력·하단 버튼 접근은 통과다. 별도 캡처는 없다.
- 이로써 갤럭시 세 입력 시트의 키보드 유지 스크롤·하단 버튼 접근을 확인했다. 이번에는 소비 확정을 요청하지 않았으며 실제 차감·재시작 후 유지 검증으로 기록하지 않는다. 다음은 남은 음식 저장부터 실제 상태 변경과 재진입 확인이다.

## Galaxy 남은 음식 저장 — 사용자 본체 확인 (2026-09-08)

- 사용자가 조리 시트를 취소한 뒤 남은 음식 `QA 카레`·`2인분`·`냉장`으로 등록하는 안내를 수행했고, 냉장고 목록에 표시된다고 확인했다. 사용자 보고 기준으로 남은 음식 저장·목록 표시는 통과다.
- 사용자가 최근 앱 화면에서 앱을 종료한 뒤 다시 실행했고, 냉장고에 `QA 카레 · 2인분`이 그대로 표시된다고 확인했다. 사용자 본체 보고 기준으로 앱 재실행 후 유지도 통과다.
- 테스트 항목은 유지한다. 별도 캡처·원격 DB 조회는 하지 않았으므로 이 결과만으로 원격 동기화 완료를 입증하지 않는다. 다음은 영수증 검수 확정 입고와 목록 반영 확인이다.

| 제한된 접근 | 통과 | 사용자가 설정에서 테스트 사진만 허용한 상태로 선택·업로드 성공 |

| 확정 입고 | 통과 | 새 초안에서 돼지고기 제외 후 `5개 냉장고에 담기` → 완료 화면 표시 |
| 보관 위치별 입고 | 통과 | 냉장: 계란 10개·두부 1모·애호박 1개 추가, 냉동: 만두 2봉 추가, 실온: 참기름 1병 추가. 기존 동명 lot는 별도로 유지 |
| 편집 시트 취소 | 수정 후 통과 | 직접 추가/남은 음식 공용 시트에 `닫기` 추가, 저장 없이 홈 복귀 확인 (`d960a6c`) |

이번 iOS 시스템 사진 선택기에는 테스트 영수증 외 사진의 썸네일도 표시됐다. 사용자가 지정한 테스트 영수증만 선택했으며, 이 관찰을 앱이 전체 사진 데이터에 접근했다는 증거로 해석하지 않는다.

검수 취소는 **재고 입고 취소**다. 이미 업로드한 원본·scan job까지 삭제되는지는 이번에 검증하지 않았고, 취소 후 원격 데이터 삭제도 수행하지 않았다. 같은 사진을 새로 업로드한 것은 새 scan job이므로 동일 batch 멱등성 검증으로 기록하지 않는다.

## 남은 검증

- iPhone 본체의 한글 화면 키보드: 입력·조합, 검수/남은 음식/조리 완료 시트의 확정·닫기 버튼 접근. 미러링 입력에서는 화면 키보드가 나타나지 않았고 한글 입력·클립보드 전달이 안정적이지 않아 검증 완료로 간주하지 않는다.
- 사진 선택 취소 후 재진입, 전체 접근, 실제 HEIC·10MB 경계·네트워크 실패 복구
- iPhone 남은 음식 저장, 조리 완료 부분·전량 차감, 재시작 후 상태 유지
- 갤럭시 사진 권한·레이아웃 및 세 흐름 전체, 접힘/펼침 상태
- 설치 가능한 preview build와 Metro 없이 실행 확인

테스트 확정 입고 5개 lot는 iPhone 데모 계정에 남겨 두었다. 기존 재고나 테스트 원본을 임의로 삭제하지 않는다. 다음 작업은 본체 키보드 QA부터 이어간다.

## 리뷰 수정 후 시뮬레이터 키보드 QA (2026-09-08)

실기기와 분리한 `Namgimeopsi QA iPhone 13 mini` / iOS 26.5 시뮬레이터에서 로컬 Debug 빌드를 실행했다. 세 시트에 공용 `KeyboardSheet`를 적용해 높이를 제한하고 전체 내용과 버튼을 스크롤하게 했다. iOS 키보드 높이에 따라 가용 영역이 줄며, 터치 스와이프는 키보드를 내린다.

| 시트 | 확인 결과 |
| --- | --- |
| 남은 음식/직접 추가 공용 편집 | 소프트웨어 한글 키보드의 자음·모음 버튼으로 `카레` 조합 입력. 마지막 권장 시점 입력란이 키보드 위에 표시됨. 스와이프 후 저장·닫기 접근 및 저장 없이 취소 확인 |
| 조리 완료 | `남은 양` 필드와 소프트웨어 키보드 동시 표시, `반 모` 값 유지. 스와이프 후 `재료 사용 완료`·`아직 있어요` 접근 및 차감 없이 취소 확인 |
| 영수증 검수 | 첫/마지막 권장일 입력란이 소프트웨어 키보드 위에 표시됨. 하단 입고·취소 버튼까지 이동 가능하며 검수 취소로 홈 복귀. `2026-09-31`은 오류·확정 비활성, `2026-09-20`은 오류 해제·확정 활성 확인 |

영수증 PNG의 시뮬레이터 가져오기 작업이 지연돼 중단하고 기본 꽃 샘플 사진으로 fixture 검수를 열었다. 실제 iPhone의 앞선 영수증 업로드 결과와 별도 기록이며, 이 시뮬레이터에서는 입고·소비·남은 음식 저장을 확정하지 않았다. 키보드 QA용 샘플 업로드/scan job은 생성됐으며 삭제하지 않았다. 이번 시각 증거도 대화의 캡처이고 별도 파일로 저장하지 않았다.

회귀 검증: `npm run test:domain`, `npm run test:receipts`, `npx tsc --noEmit`, `npm run lint`, `npx expo export --platform web` 통과. 새 테스트는 날짜 수정→입고→추천 상태, 잘못된 달력 날짜·빈 날짜·제외 항목, 닫힌 요청 A가 새 요청 B보다 늦게 완료되는 경우를 다룬다. 지연 응답 테스트는 요청 세션 단위 테스트이며 Android 본체 네트워크 지연 재현을 대체하지 않는다.

시뮬레이터 결과는 실제 iPhone 본체와 갤럭시의 입력·키보드 QA 완료로 간주하지 않는다. 위 남은 실기기·preview 항목은 유지한다.
