## 실제 iPhone 미러링 후속 QA (2026-09-08, `7d94a61` 이후)

iPhone 13 mini / iOS 26.6.1을 USB로 연결하고 Mac iPhone 미러링으로 직접 조작했다. 미러링 재개 시 Mac 암호 입력이 필요해 사용자에게 잠금 해제만 요청했다. 아래 결과는 시뮬레이터와 별도인 **실제 iPhone 앱 결과**이며, 본체 화면 키보드나 사람의 손가락 터치를 직접 관찰한 결과는 아니다.

### 조작 실수와 보존된 테스트 데이터

- 첫 검수 취소 시도에서 **에이전트가 탄성 스크롤이 멈추기 전에 취소 위치를 눌러 입고 버튼을 선택했다.** fixture 6개가 batch `receipt-scan-1788857458575-wr12qfzx`로 입고됐다. 즉시 사용자에게 알렸으며 앱의 자동 입고 결함이나 취소 성공으로 기록하지 않는다.
- 이 6개 lot를 삭제·초기화하지 않았다. 이후 조리 QA는 이 새 batch의 두부와 애호박에 적용했다. 기존 5개 영수증 lot와 시드 lot는 별도로 유지됐다.
- 남은 음식 lot는 `inventory-1788860060723`, 조리 세션은 `cooking-1788860288115-3`이다. 해당 batch 두부의 `consume / remainingQuantityLabel=0.5 block`, 애호박의 `consume-all` 원장 2건을 USB로 읽은 재고 캐시에서 확인했다.
- 최종 캐시는 lot 17개·원장 13개다. 전량 소비 lot 자체는 보존되고 활성 목록에서만 제외된다. 기존 lot ID와 수량을 대조해 새 부분 소비 대상 외의 lot가 유지됨을 확인했다. 원격 재조회로 달라진 배열 순서와 동등한 UTC 날짜 표기(`Z`/`+00:00`)를 정규화한 뒤, 지연 닫기와 최종 검수 취소 전후 모든 필드가 일치했다. 원격 DB를 직접 조회한 검증은 아니다.

### 실제 iPhone 진행 중 닫기 — 20초 성공 응답 전달 지연

- 실제 기기에 임시 로컬 Release QA 빌드를 갱신 설치했다. 시뮬레이터와 같은 방식으로 업로드·분석 호출의 `await` 직후, `isCurrent()` 검사 전에 각각 20초를 기다렸다. 실제 업로드·fixture 분석은 유지했으며 네트워크 차단/지연 실패 테스트는 아니다.
- 업로드 단계 `닫기` → 홈 → 즉시 재진입 → 20초 이상 지난 후 등록 방식 화면 유지: 통과.
- 분석 단계의 제공자 미연결·fixture 고지와 `닫기` → 홈 → 즉시 재진입 → 20초 이상 지난 후 등록 방식 화면 유지: 통과.
- 두 닫기 전후 재고·원장 내용은 불변이었다. 원본·scan job은 삭제하지 않았다.
- 임시 소스는 빌드 직후 원문 복원했고, QA 후 원래 소스로 Release를 재빌드·갱신 설치했다. 코드 서명 검증과 최초 원래 JS 번들 해시 일치를 확인했다. 최종 앱에는 지연 코드가 없다. 상세는 [iOS preview 기록](11-ios-preview.md)을 따른다.

### 남은 입력·제스처 범위

- 미러링은 Mac 키보드로 입력하며 본체 소프트웨어 한글 키보드가 나타나지 않았다. 한글/클립보드 전달도 안정적이지 않아 **본체 한글 조합·키보드 열린 상태의 손가락 스와이프**는 여전히 미확인이다. 미러링 스크롤 성공을 사람의 직접 터치 결과로 표현하지 않는다.
- 전용 시뮬레이터 남은 음식 시트에서 입력칸 바깥 여백을 위로 드래그한 뒤 키보드가 내려가고 저장·닫기 전체가 보이는 것을 추가 관찰했다. 긴 영수증 목록에서는 이번에도 드래그·휠에 따른 명확한 이동을 얻지 못했다. 해당 검수는 접근성 취소 버튼으로 닫았고 추가 저장·소비는 없었다.
- 캡처는 대화에서만 확인했다. 개인 사진 썸네일이나 인증 정보는 저장소에 추가하지 않았고, 기기 캐시 대조 파일은 Git 제외 `.expo/ios-preview/device-qa/`에만 있다.

## iOS 시뮬레이터 Release 후속 QA (2026-09-08)

사용자 요청으로 `Namgimeopsi QA iPhone 13 mini` / iOS 26.5 전용 시뮬레이터에서 진행했다. 시작 HEAD는 `bb3258e`이며 앱 소스는 `cd8b625`와 같다. 기존 앱 위에 최신 Release를 설치했고 재고를 초기화하지 않았다. 아래는 에이전트가 직접 조작·관찰한 **시뮬레이터 결과**다. 실제 iPhone 본체 QA를 대체하지 않는다.

### 입력·저장·차감

| 항목 | 결과와 관찰 |
| --- | --- |
| 영수증 업로드·검수 | 지정된 테스트 영수증 PNG를 시뮬레이터 사진 앱으로 가져와 선택했다. 실제 업로드·fixture 검수 진입과 제공자 미연결 고지를 확인했다. |
| 영수증 한글 입력 | 소프트웨어 한글 키보드의 `ㅋ·ㅏ·ㄹ·ㅔ` 버튼으로 이름 `카레`를 조합했다. 빈 이름일 때 입고 버튼 비활성, 입력 후 활성화를 확인했다. |
| 영수증 마지막 필드·취소 | 접근성 요소로 마지막 권장일 필드에 포커스하자 목록이 이동하고 해당 필드가 키보드 위에 표시됐다. 키보드를 닫은 뒤 `6개 냉장고에 담기`·`아직 저장하지 않을게요` 전체를 확인하고 취소했다. 추가 입고는 확정하지 않았다. |

| 저장 원장 대조 | 앱 컨테이너의 재고 캐시에서 lot `tofu`의 `반 모`, `zucchini`의 `consume-all`, 같은 `cooking-1788859014389-2` 세션의 원장 2건을 확인했다. 전량 소비 lot 자체는 보존되고 `getActiveInventoryItems`에서 제외된다. 저장된 outbox는 0건이었다. 원격 DB를 직접 조회한 검증은 아니다. |

**스크롤 범위:** 이번 Computer Use의 휠 스크롤·드래그는 시뮬레이터에서 일관된 목록 이동을 만들지 못했다. 마지막 필드의 접근성 포커스에 따른 자동 스크롤과 키보드 회피·버튼 표시는 확인했지만, 손가락 스와이프·키보드 유지 스크롤을 신규 통과로 기록하지 않는다. 이전 시뮬레이터의 스와이프 관찰 및 실제 본체 QA와 구분한다. Mac 키 입력으로 한글을 전송하는 것은 안정적이지 않아 실제 한글 조합은 소프트웨어 키보드 버튼으로 수행했다.

### 업로드·분석 중 닫기 — 인위적 응답 지연 조건

- 원래 Release에서는 응답이 빨라 업로드 단계 감지 뒤 클릭하는 사이 검수로 전환됐다. 이를 닫기 성공으로 세지 않았다.
- 네이티브 시트에서 누를 시간을 확보하기 위해 `ReceiptEntrySheet.tsx`의 업로드·분석 `await` 직후, `isCurrent()` 검사 전에 각각 15초를 기다리는 임시 시뮬레이터 QA 빌드를 만들었다. 실제 사진 선택·업로드·fixture 분석 호출은 유지했다. 네트워크 요청을 지연하거나 실패시킨 테스트는 아니며 **성공 응답의 UI 전달 지연**이다.
- 업로드 단계의 `닫기` 표시·터치 → 홈 복귀 → 즉시 `+` 재진입 → 15초 이상의 지연 완료 후에도 등록 방식 선택 화면 유지: 통과.
- 분석 단계의 제공자 미연결·fixture 고지와 `닫기` 표시·터치 → 홈 복귀 → 즉시 재진입 → 지연 완료 후에도 등록 방식 선택 화면 유지: 통과.
- 두 경우 후 로컬 재고·원장 전체가 조리 QA 직후 상태와 동일함을 대조했다. 추가 입고는 없고, 업로드 원본·scan job은 삭제하지 않았다. 지연 실패 응답은 이번 시뮬레이터에서 유발하지 않았으며 기존 `test:receipts` 자동 테스트의 범위다.
- 임시 지연은 빌드 직후 원문으로 복원했고 `git diff --exit-code -- src/features/receipts/ReceiptEntrySheet.tsx`를 통과했다. 검증 후 지연 없는 원래 Release를 재빌드·갱신 설치했으며 최초 원래 번들 해시와 일치했다. 최종 실행에서도 저장·차감 상태를 다시 확인했다. 빌드·복원 결과는 [iOS preview 기록](11-ios-preview.md)을 따른다.

이번 화면 증거는 대화의 Simulator 캡처이며 별도 이미지 파일은 저장소에 추가하지 않았다. 테스트 남은 음식과 소비 원장은 보존한다. 이후 실제 iPhone 미러링 저장·차감 및 응답 지연 조건의 닫기를 확인했으며 최신 결과와 본체 키보드의 남은 범위는 위 후속 기록을 따른다.

## iPhone Release QA (2026-09-08, `cd8b625`)

- iPhone 13 mini의 실제 OS는 26.6.1이다. USB 통신·페어링·개발자 모드·미러링을 확인했다. 기존 설치는 Metro 부재 시 시작 오류를 보였으며, 버전 번호만으로 기존 설치의 소스 커밋은 확인할 수 없다.
- 최신 코드로 Apple Development 서명된 로컬 Release를 빌드하고 기존 앱 위에 설치했다. Metro 없는 cold launch·기존 냉장 lot 표시를 직접 확인했다. 빌드·서명 만료·재현 명령은 [iOS preview 기록](11-ios-preview.md)을 따른다.
- 미러링에서 지정된 테스트 영수증을 선택해 업로드 → 검수 진입과 제공자 미연결·fixture 고지를 직접 확인했다. 추가 입고는 확정하지 않았다. 개인 사진 썸네일을 저장소에 추가하지 않았다.
- 업로드 단계의 새 `닫기` 표시는 관찰했다. 사진 선택 후 닫기 터치 시에는 이미 검수로 넘어가 있어, 진행 중 닫기 성공으로 기록하지 않는다. 분석 단계의 표시·닫기 및 닫기 후 재진입은 미확인이다.
- 본체 영수증 키보드 확인을 요청한 뒤, 사용자가 시뮬레이터 검증으로 진행하도록 요청했다. 위 후속 QA를 수행했으며 본체 결과 보고는 아직 없다. 남은 음식·조리 시트의 본체 키보드와 저장·부분/전량 차감·재실행 유지는 미완료다. 시뮬레이터·자동 회귀 테스트 성공으로 대체하지 않는다.

## Galaxy 키보드 회피 수정 및 스크롤 확인 (2026-09-08)

- SM-F766N / Android 16에서 최신 로컬 Debug 빌드·설치에 성공했다. 테스트 영수증은 사용자가 기기에 저장했다고 확인했다.
- 남은 음식 등록 시 사용자가 본체에서 입력칸/버튼이 키보드에 가려지고 스크롤도 되지 않는다고 보고했다. 직접 캡처로 확인한 결과와 구분한다.
- 공용 `KeyboardSheet`의 Android `behavior`가 미지정이었던 것을 `height`로 변경했다. 키보드가 차지하는 높이에 맞춰 스크롤 영역을 줄이도록 했으며 iOS의 `padding`은 유지한다.
- `height`만 적용한 뒤 사용자가 버튼 끝만 보이고 스크롤하면 키보드가 닫힌다고 보고했다. 전문 에이전트가 설치된 React Native의 Android ScrollView 구현에서 `on-drag`가 `dismissKeyboard()`를 호출하는 것을 확인했다. Android에만 `keyboardDismissMode="none"`을 적용했고 iOS 동작과 버튼의 `keyboardShouldPersistTaps="handled"`는 유지했다.
- 수정 후 연결된 갤럭시에서 ADB 터치 스와이프와 화면 캡처로 한글 키보드가 열린 채 마지막 권장 시점·`냉장고에 담기`·`닫기` 전체가 보이는 것을 직접 확인했다. 기존 `카레`·`2인분` 값도 유지됐다. 이번에는 저장을 누르지 않았으며 이후 시스템 뒤로가기로 시트가 닫혀 홈으로 복귀했다.
- TypeScript·lint·diff 검사 통과. 사용자도 본체에서 스크롤이 잘 되고 끝까지 내리면 버튼이 잘 보인다고 재확인했다. 남은 음식 시트의 키보드 유지 스크롤·하단 버튼 접근은 통과로 기록한다. 영수증·조리 완료 시트의 후속 확인은 아래에 기록한다. 키보드 재열기 반복은 별도 확인이 남아 있다. 캡처는 임시 파일로만 확인했으며 저장소에 추가하지 않았다.

| 영수증 검수 | 첫/마지막 권장일 입력란이 소프트웨어 키보드 위에 표시됨. 하단 입고·취소 버튼까지 이동 가능하며 검수 취소로 홈 복귀. `2026-09-31`은 오류·확정 비활성, `2026-09-20`은 오류 해제·확정 활성 확인 |

영수증 PNG의 시뮬레이터 가져오기 작업이 지연돼 중단하고 기본 꽃 샘플 사진으로 fixture 검수를 열었다. 실제 iPhone의 앞선 영수증 업로드 결과와 별도 기록이며, 이 시뮬레이터에서는 입고·소비·남은 음식 저장을 확정하지 않았다. 키보드 QA용 샘플 업로드/scan job은 생성됐으며 삭제하지 않았다. 이번 시각 증거도 대화의 캡처이고 별도 파일로 저장하지 않았다.

회귀 검증: `npm run test:domain`, `npm run test:receipts`, `npx tsc --noEmit`, `npm run lint`, `npx expo export --platform web` 통과. 새 테스트는 날짜 수정→입고→추천 상태, 잘못된 달력 날짜·빈 날짜·제외 항목, 닫힌 요청 A가 새 요청 B보다 늦게 완료되는 경우를 다룬다. 지연 응답 테스트는 요청 세션 단위 테스트이며 Android 본체 네트워크 지연 재현을 대체하지 않는다.

시뮬레이터 결과는 실제 iPhone 본체와 갤럭시의 입력·키보드 QA 완료로 간주하지 않는다. 위 남은 실기기·preview 항목은 유지한다.
