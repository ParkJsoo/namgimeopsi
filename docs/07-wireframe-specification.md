# Wireframe specification

## Prototype path

포트폴리오 데모에서 사용하는 대표 시나리오는 다음과 같다.

```text
장 본 뒤 영수증 촬영
→ AI가 8개 후보를 추출
→ 모호한 한 개를 수정하고 입고
→ 홈에서 남은 치킨과 임박 두부를 확인
→ 오늘의 메뉴 선택
→ 조리 완료 후 두부·계란 잔량 차감
```

## Screen 01 — Onboarding

### Goal

사용자에게 앱의 약속을 이해시키고 메뉴 추천에 필요한 최소 설정만 받는다.

### Content

- 헤드라인: `냉장고에 있는 걸, 오늘 저녁으로 바꿔드릴게요.`
- 보조 문장: `장을 본 재료와 남은 음식을 잊기 전에 먼저 챙겨드려요.`
- 가구 인원: `1인` / `2인`
- 기본 보유 재료 선택: 소금, 식용유, 간장, 고추장, 설탕
- CTA: `내 냉장고 시작하기`

### Layout

```text
  [warm food illustration / product mark]

  냉장고에 있는 걸,
  오늘 저녁으로 바꿔드릴게요.

  함께 먹는 인원      [ 1인 ] [ 2인 ]
  기본으로 갖고 있어요 [ 소금 ] [ 식용유 ] ...

  [          내 냉장고 시작하기          ]
```

## Screen 02 — Home

### Goal

목록 탐색이 아니라 오늘의 다음 행동을 빠르게 결정시킨다.

### Content

- 인사: `화요일 저녁, 오늘 먼저 먹을 게 있어요`
- 우선 소비 카드: 남은 치킨 / 두부 / 애호박
- 메뉴 섹션: 최대 세 개의 레시피 카드
- 하단 FAB: `+ 추가`

### Layout

```text
  안녕하세요, 윤서님                  [알림]
  오늘 먼저 먹으면 좋은 것

  [ 남은 치킨       오늘 드시는 걸 권장해요  > ]
  [ 두부 · 애호박  이틀 안에 써보세요     > ]

  오늘의 한 끼                            모두 보기
  [ 치킨마요 덮밥               15분 / 1인분 ]
    남은 치킨을 오늘 쓰기 좋아요 · 부족 재료 없음
  [ 애호박 두부덮밥             15분 / 1인분 ]

  [ 홈 ]       [ 냉장고 ]       [ 나 ]
                    [ + 추가 ]
```

## Screen 03 — Quick add bottom sheet

### Goal

입력 방법을 세 개로 제한해 선택 피로를 없앤다.

### Choices

- `영수증으로 등록` — 장 본 것을 한 번에 담기
- `남은 음식` — 배달·반찬을 5초 만에 기록
- `직접 추가` — 지금 있는 재료 하나 넣기

## Screen 04 — Receipt capture

### Goal

AI 분석에 필요한 선명한 입력을 얻는다.

### Content

- 상단 가이드: `영수증 전체가 프레임 안에 들어오게 찍어주세요.`
- 화면 중앙의 문서 윤곽 오버레이
- `갤러리에서 선택` 보조 행동
- 큰 촬영 버튼

실제 구현에서는 카메라 권한 거부 상태와 흐린 이미지 재촬영 안내를 포함한다.

## Screen 05 — AI analysis

### Goal

대기 시간이 무의미하게 느껴지지 않게 하고, 결과가 확정값이 아님을 미리 알린다.

### Content

```text
  장 본 것을 정리하고 있어요

  ✓ 영수증 글자를 읽었어요
  • 상품명을 식재료로 바꾸고 있어요
  ○ 보관 위치와 권장 시점을 제안할게요

  결과는 저장 전에 직접 확인할 수 있어요.
```

## Screen 06 — Receipt review

### Goal

이 앱의 대표 화면이다. AI 결과를 빠르게 통제하고 입고를 확정한다.

### Structure

```text
  <  장 본 것 확인                     8개 찾음
  AI가 읽은 결과예요. 맞는지만 확인해 주세요.

  확인됨 6
  [ 계란         10개   냉장   09.10까지       > ]
  [ 두부          1모   냉장   08.29 권장      > ]
  [ 냉동만두      2봉   냉동   11.25까지       > ]

  확인 필요 2
  [ 백설 진한참기름  1병  AI 추정: 참기름      > ]
  [ 한돈 앞다리    1팩  AI 추정: 돼지고기      > ]

  [            8개 냉장고에 담기             ]
```

### Item edit

행을 탭하면 작은 바텀시트에서 다음을 바꾼다.

- 식재료 이름 및 원문 확인
- 수량과 생활 단위
- 냉장 / 냉동 / 실온 위치
- 포장 표기일 또는 권장 섭취 시점
- 제외

## Screen 07 — Intake complete

### Goal

입고 완료를 축하하고 바로 제품 가치로 연결한다.

```text
  8개를 냉장고에 담았어요.
  두부와 앞다리살은 이번 주 안에 먼저 써보세요.

  [ 오늘의 한 끼 보기 ]
  [ 냉장고 목록으로 ]
```

## Screen 08 — Leftover registration

### Goal

남은 음식이 생긴 순간, 복잡한 설명 없이 기록하게 한다.

### Fields

- 사진 추가: 선택
- 이름: `남은 마라탕`
- 양: `1인분` / `2인분` / `조금 남음`
- 위치: 냉장 기본값
- 보관 시작: `지금`
- 안내: `포장 표기일이 아닌 권장 섭취 시점이에요.`
- CTA: `남은 음식 담기`

## Screen 09 — Inventory

### Goal

사용자가 재고를 찾아보고 정정할 수 있는 조용한 관리 화면이다.

### Content

- 보관 위치 세그먼트: 냉장 / 냉동 / 실온
- 정렬: `먼저 먹기` 기본값
- 항목 행: 식재료명, 남은 양, 위치, 날짜 상태
- 필터: 남은 음식 / 확인 필요 / 임박

## Screen 10 — Recipe detail

### Goal

사용자가 이 메뉴를 선택할 근거를 확인하고 조리로 진입한다.

### Content

- 음식 이미지, 이름, 시간, 인분
- 추천 이유: `남은 치킨과 계란을 오늘 쓰기 좋아요.`
- 재료 체크: 보유 / 부족 / 기본 보유 재료
- 조리 단계
- 고정 CTA: `만들기 시작`

## Screen 11 — Completion and consumption

### Goal

재고 상태를 최신으로 유지하되 실제 사용량 수정은 가볍게 만든다.

### Content

```text
  치킨마요 덮밥, 맛있게 드셨나요?
  실제로 쓴 만큼만 확인해 주세요.

  [✓] 남은 치킨          1인분 → 다 먹음
  [✓] 계란               1개 → 9개 남음
  [✓] 밥                 1공기 → 조금 남음

  [     재료 사용 완료     ]
```

완료 후 홈으로 돌아가면 우선 소비 카드와 레시피 순위가 갱신되어야 한다.

## Edge states to design

| State | User-facing response |
| --- | --- |
| AI 분석 실패 | `항목을 읽지 못했어요. 직접 추가하거나 다시 찍어볼까요?` |
| 재고가 비어 있음 | `오늘 장 본 것을 영수증으로 한 번에 담아보세요.` |
| 추천 메뉴 없음 | `부족한 재료가 너무 많아요. 재고를 더 추가하거나 장보기 목록을 확인해 보세요.` |
| 권장 섭취 시점 지남 | `상태를 확인해 주세요. 먹었나요, 아직 있나요, 정리할까요?` |
| 알림 수신 | `남은 치킨을 오늘 저녁 후보에 넣을까요?` |
