# 전체 데모 리허설 — 2026-09-09

**세 흐름의 실제 입력·저장·소비와 앱 재실행 검증을 완료했다.** 날짜 저장·표시의 한계를 발견했으므로 본촬영 전에 별도 앱 수정으로 다룬다. 이 문서는 리허설 결과이며 최종 영상 완성을 뜻하지 않는다.

사용자가 확인한 `smoke-10s-playback.mp4`는 녹화·재생 시험 전용이다. **최종 영상에 사용하지 않는다.** 이번 리허설도 장면별 XCTest 실행·스크린샷·재고 대조로 수행했으며, 연속 원테이크 촬영이나 120초 편집본은 만들지 않았다.

- 전체 원본은 Git 제외 `.expo/demo-production/`에 남겼다. 아래 선별 화면은 저장소에 보존했다.

## 실제 메뉴와 동선

영수증·카레 등록 후 순위는 다음과 같았다.

1. **애호박 두부덮밥:** 15분 / 1인분, 부족 재료 없음, `두부와 애호박을 먼저 쓰기 좋아요`.
2. **치킨마요 덮밥:** 15분 / 1인분, 부족 재료 없음, 남은 치킨 활용 이유.
3. **만두 계란국:** 20분 / 2인분, 부족 재료 대파.

첫 메뉴 카드를 누르면 현재 구현은 바로 `조리·섭취를 완료할까요?` 시트를 연다. 레시피 상세·조리 단계·타이머를 시연했다고 표현하지 않는다. 메뉴 순위는 실제 재고 기준이며 촬영 직전에 다시 확인한다.

### 장면별 시간

XCTest 로그의 `REHEARSAL` 타임스탬프 차이다. 스크린샷·UI 안정화 대기를 포함하며 사람의 수행 속도나 순수 네트워크 지연이 아니다. 빌드·장면 사이 데이터 대조 시간은 제외했다.

| 장면 | 관찰 시간 | 편집·촬영 기준 |
| --- | --- | --- |
| 검수 시작 → 참기름 한글 수정 → 돼지고기 제외 → 확정 버튼 도달 | 19.20초 | 긴 검수 목록의 스크롤은 축약 가능, 수정값·제외 상태·확정 버튼은 읽히게 유지 |
| 영수증 확정 버튼 → 완료 화면 | 1.52초 | 실제 저장 완료 화면 유지 |
| 남은 음식 진입 → 이름 입력 → 저장 후 폼 닫힘 | 12.15초 | `1인분`, `냉장`, 권장 시점 입력 문구 확인 |
| 메뉴 선택 → 두부 `반 모` 입력 → 확정 준비 | 8.38초 | 두부·애호박 행과 선택 상태를 함께 보여 주기 |
| 재료 사용 완료 → 완료 시트 닫힘 | 1.83초 | 최종 목록·동명 lot 차이를 함께 설명 |

사진 선택·업로드는 앞 시험 단계에서 성공했지만 별도 구간 계측을 하지 않았다. 이 표를 합해 전체 사용자 여정 시간으로 발표하지 않는다.

## 본촬영 전 수정할 날짜 문제

1. **남은 음식의 실제 날짜가 저장되지 않는다.** 카레의 `recommendedUseByAt`은 없고 `recommendedUseBy="내일까지"`, `storageStartedAt="지금"`만 저장된다. `createdAt`은 실제 ISO 시각이다. `use-inventory.ts:createItem`도 이 문구 저장을 확인했다. 날짜가 지나도 상대 문구가 자동 갱신되는 기능으로 설명하면 안 된다.
2. **목록의 상대 문구와 추천 날짜 기준이 다르다.** 영수증 두부의 추천용 날짜는 `2026-09-01`인데 목록은 `이번 주 안 권장`이라고 표시한다. 기존 시드 역시 촬영일보다 과거인 ISO 날짜와 `이틀 안` 등 고정 문구가 함께 존재한다. `types.ts:getFoodStatus`는 상대 문구로 목록 상태를 계산하는 반면 메뉴 추천은 ISO 날짜를 사용한다. 촬영일 기준으로 일관된 날짜 표시·상태 계산을 별도 앱 수정에서 다뤄야 한다.

리허설의 저장·소비 확인은 완료했으나, 날짜 관리가 완성됐다고 주장하거나 이 불일치를 편집으로 숨긴 최종 영상은 만들지 않는다. 날짜 수정은 준비 문서 PR과 분리하고 검증 후 촬영 대본을 다시 확정한다. OCR 제공자 연결은 범위에 추가하지 않는다.

## 재현 자료와 다음 출발점

`.expo/demo-production/` 안에 `rehearsal-01-edit-retry.xcresult`부터 `rehearsal-06-restart.xcresult`, 같은 이름의 로그, 장면별 JSON, `verify-rehearsal.py`와 통과 결과 `rehearsal-verification.txt`가 있다. `Rehearsal/01-edit.swift.txt`부터 `06-restart.swift.txt`는 각 장면 실행 당시 소스다. 이 runner들은 화면 사전 조건을 요구한다. **현재 최종 상태에서 저장 단계를 무조건 재실행하지 않는다.**

첫 edit runner는 XCTest 쿼리의 `.count`/`.element`를 잘못 사용해 컴파일 실패했다. `.matching(identifier:)`로 고친 뒤 6개 장면 테스트를 모두 통과했다. 이는 앱 결함이나 저장 실패가 아니다. 재고 대조도 처음에는 소진 lot가 원본 배열에서 제거된다고 가정했고, 이후 원장으로 활성 여부를 계산하는 실제 모델과 ISO 시각 정규화에 맞춰 검증했다. 원본 실패 로그는 보존한다.

현 전용 시뮬레이터는 리허설 종료 재고를 유지한다. 다음 순서는 날짜 저장·표시 수정 → 해당 시뮬레이터 회귀 확인 → 리허설 데이터를 보존하는 별도 본촬영 세션 준비 → 장면별 본촬영·편집이다. 촬영용 시작 재고는 아직 준비하지 않았다. 테스트 영상·리허설 화면을 최종 촬영본으로 재사용하지 않는다.
