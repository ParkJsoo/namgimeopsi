# Development roadmap

## Delivery principle

4~6주 안에 세 개의 핵심 흐름을 끝까지 실제로 동작하게 만든다. 범위를 넓히기보다 AI 실패·빈 상태·수정·차감 같은 상태 변화를 완성한다.

## Six-week plan

| Week | Deliverable |
| --- | --- |
| 1 | 와이어프레임, 디자인 토큰, Expo·Supabase 초기화, 익명 로그인, 시드 데이터, 수동 재고 CRUD |
| 2 | 홈 임박 집계, 재고 필터·상세 수정, 남은 음식 등록, 소비·폐기 이벤트 |
| 3 | 영수증 촬영·업로드, `scan_jobs`, AI 분석 함수, 검수형 입고, 영수증 fixture 10장 |
| 4 | 레시피 매칭, 메뉴 상세, 조리 완료와 재료 차감, 로컬 알림 |
| 5 | 오류·빈 상태, 수량·날짜 예외 처리, 실기기 QA, UI 완성도, 테스트 |
| 6 | 3~5명 사용성 테스트, 수정 반복, EAS preview build, 데모 영상·README·케이스 스터디 |

## Definition of done

### Product

- 영수증 촬영부터 입고 완료까지 하나의 실데이터 흐름으로 동작한다.
- 홈이 저장된 재고와 날짜에 따라 우선 소비 항목·메뉴를 바꿔 보여 준다.
- 조리 완료 후 여러 재고 항목의 잔량·이력이 갱신된다.
- 남은 음식은 재료와 다른 날짜 의미를 가진 별도 재고로 관리된다.

### Quality

- 권한 거부, 업로드 실패, AI 분석 실패, 빈 재고, 저신뢰 인식 결과를 처리한다.
- 날짜와 수량 계산 로직을 테스트한다.
- iOS 또는 Android 실기기에서 카메라·알림을 시연한다.
- 실제 기능과 향후 목업 기능을 README에서 분리해 설명한다.

## Portfolio artifacts

### README

- 30~45초 제품 GIF 또는 영상
- 문제, 타깃, 핵심 흐름
- 시스템 구조와 AI 파이프라인
- 기술 선택과 트레이드오프
- 실행 방법과 환경 변수

### Case study

```text
문제 관찰
→ 경쟁 서비스 조사
→ 타깃 축소
→ 제품 가설
→ UX 설계
→ AI 신뢰 UX 결정
→ 구현과 사용성 테스트
→ 배운 점과 다음 실험
```

### Demo video

2분 이내에 다음을 보여 준다.

1. 문제와 타깃: 10초
2. 영수증 촬영·AI 검수·입고: 35초
3. 임박 재료 기반 메뉴 선택: 25초
4. 조리 완료·재고 차감: 25초
5. AI 신뢰 UX와 기술 판단: 25초

## Stretch goals

핵심 MVP 완료 후에만 고려한다.

- 사용자 수정 이력을 반영한 개인별 영수증 별칭 학습
- 비공개 공유 냉장고 프로토타입
- 레시피 대체재 제안
- 사용성 테스트 기반 추천 카드 개선
