사용자 요청으로 코드·회귀 담당과 화면·검증 근거 담당 두 전문 에이전트가 `d9bd8ce`를 독립 검토했다. 기존 동명 재고 선택 불일치는 해결 판정이며, 새 P2 1건을 재현했다. 이번 작업은 리뷰와 기록이며 앱 소스 수정은 하지 않았다.

## P2 — 부분 소비 후 같은 메뉴 재진입 시 과거 수량 초안 재사용

`src/features/recipes/RecipeCompletionSheet.tsx:128`은 확정 직후 소비 전 `defaultDraft`를 저장한다. 32행의 key는 recipe ID와 lot ID만 포함하고, 40행은 같은 key의 저장 초안을 다시 사용한다. 숨김 렌더를 거쳐도 저장 초안 자체는 무효화되지 않는다.

1. 두부 `1모`로 메뉴 완료 시트를 연다.
2. 남은 양 `반 모`를 입력하고 확정한다.
3. 같은 메뉴를 다시 연다. 현재 재고는 `반 모`다.
4. `남은 양`을 누르면 입력에는 과거 `1모`가 남고 완료 버튼이 활성화된다.
5. 그대로 확정하면 재고가 `1모`로 증가하고 소비 원장이 추가된다.

코드 에이전트가 실제 시트 컴포넌트와 실제 `completeCookingSession`을 모의 React/native 호스트에서 연결해 재현했다. 변경된 재고 props와 `visible=false → 재오픈`을 포함했다. 네이티브나 서버 데이터에 이 오류를 실행하지는 않았다.

**다음 수정:** 닫기·확정 후 이전 세션 초안을 무효화하고, 다음 진입 때 최신 재고를 사용한다. 현재 recipes 테스트는 같은 props 재렌더와 취소 초기화를 확인하지만, 부분 소비 후 갱신된 수량·닫힘·재오픈을 연결하지 않는다. 이 재현을 회귀 테스트에 추가해야 한다.
