## P2 — 동명 lot의 추천 근거와 차감 대상이 다름 (후속 수정 완료)

아래는 발견 당시 기록이다. 공통 선택 기준·lot 선택 UI와 자동/네이티브 회귀 검증을 완료했다. [후속 검증](19-lot-selection-qa.md).

기존 결함이며 최근 날짜 수정에서 새로 생긴 회귀는 아니다.

- `src/features/recipes/recommendations.ts:31`은 같은 이름의 재고 중 가장 긴급한 상태를 추천 근거로 선택한다.
- `src/app/index.tsx:128`은 완료 시트 대상으로 원본 배열의 첫 동명 lot만 선택한다.
- `src/features/recipes/RecipeCompletionSheet.tsx:66`에는 이름과 현재 양만 표시되어, 같은 두부 1모 두 개를 구분하거나 다른 lot를 선택할 수 없다.

**재현:** 기준일 2026-09-14, 배열 순서가 새 두부 `1모 / 9월 20일`, 기존 두부 `1모 / 9월 13일`, 애호박일 때 추천은 “두부: 기준 날짜가 지났어요”라고 설명한다. 완료 시트는 새 두부를 선택하고 `다 먹음`을 확정하면 새 두부가 차감되어 지난 날짜의 기존 두부만 남는다.

코드 에이전트가 화면 선택 함수의 원문을 추출·transpile 실행하고 실제 추천·원장 함수를 연결해 재현했다. 메인도 서로 다른 선택 기준을 확인했다. 현재 영상은 품목별 lot가 하나이므로 영상 속 차감 결과에는 영향이 없다.

**다음 조치:** 추천과 차감 후보의 선택 기준을 맞추고, 시트에서 날짜·보관 위치 등으로 lot를 구별할 수 있게 한다. 동명 lot의 추천 근거 → 시트 선택 → 최종 원장 연결 회귀가 필요하다. 사용자가 실제로 쓴 lot를 바꿀 수 있는 흐름도 함께 검토한다.

## 최근 날짜 수정 재검토

- 날짜 삭제 후 시드 날짜를 재주입하던 로직 제거와 overdue 추천 문구 보완은 정상이다.
- 코드 에이전트가 inventory hook 8개와 날짜/추천 9개를 실행했고 모두 통과했다. 추가 P1 또는 새 날짜 회귀는 발견하지 못했다.
- 날짜 삭제 테스트는 온라인 삭제 후 오프라인 재실행·재연결을 다룬다. 오프라인에서 삭제한 pending 작업을 원격 hydration 위에 재적용하는 경우는 추가 검증 후보이며, 재현된 결함으로 판정하지 않았다.

## 영상 독립 검토 — P2 이상 발견 없음

실제 MP4의 핵심·경계 프레임 23장과 전체 디코딩을 확인했다. 독립 리뷰에서 플레이어 연속 재생은 반복하지 않았다. 직전 제작 QA의 QuickTime 끝까지 재생 확인과 구분한다.

| 최종 영상 구간 | 확인 내용 |
| --- | --- |
| 00:30–00:42 | 참기름 1병 → 조금 남음, 돼지고기 제외, 5개 확정 버튼 |

핵심 확정 과정 누락이나 실제 OCR로 오해시키는 설명은 확인되지 않았다. 확인 프레임에는 테스트 영수증·기본 풍경 사진만 있고 개인 사진·키·서버 주소 노출을 발견하지 못했다. fixture·시뮬레이터·무음·축약 고지가 유지된다.

**P3 편집 개선 후보:**

1. 01:10–01:12에는 남은 음식 설명 중 화면이 홈으로 이동한다. 01:08–01:09에 날짜 결과는 이미 보이므로 누락은 아니지만, 저장 결과를 더 유지하면 장면 설명과 맞는다.
2. 앱 화면은 1920px 중 444px 폭이다. 좁은 포트폴리오 임베드에서는 작은 날짜·추천 근거 글씨가 읽기 어려울 수 있으므로, 공개 위치의 실제 크기에서 확인하고 필요하면 핵심 장면을 확대한다.
