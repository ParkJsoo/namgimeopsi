## 발견 사항

### P2 — 지운 예제 재고 날짜가 오프라인 재실행 때 복원됨

`src/features/inventory/use-inventory.ts:146`은 매 hydration마다 `mergeMissingRecommendationDates`를 호출한다. `src/features/inventory/ledger.ts:138`은 사용자 의도와 무관하게 날짜가 없는 시드 ID의 날짜를 채운다.

실제 함수 조합으로 시드 `tofu`에 `applyDraftDates`의 빈 날짜를 적용한 뒤 hydration 보완 함수를 실행했다. 결과는 `null → 2026-08-31`이었다. 온라인 원격 조회가 성공하면 원격 상태로 덮어써질 수 있지만, 오프라인 경로는 복원된 날짜를 유지·저장하며 bootstrap queue에도 실을 수 있다. 신규 생성 lot에는 해당하지 않으며 현재 비운 Demo 재고가 다시 생성된다는 뜻도 아니다.

수정 방향: 명시적으로 지운 날짜와 과거 미이관 상태를 구분하거나 이 보완 로직을 제거한다. 날짜 삭제 → 오프라인 재실행 → 연결 복구까지 실제 hydration을 실행하는 회귀 검증이 필요하다. 현재 persistence harness는 `useEffect`를 생략하고 빈 seed를 사용하므로 이 문제를 잡지 못한다.

### P2 — 지난 날짜가 추천 이유에서는 사용 권유로 바뀜

`src/features/domain/recipe-ranking.ts:88`은 overdue·today·soon을 같은 그룹에 넣고, `:55`는 모두 “먼저 쓰기 좋아요”라고 출력한다. 날짜 수정에서 홈·목록은 상태 확인 문구로 바뀌었지만 추천 카드는 그대로다.

시드 재고를 기준일 `2026-09-14`에 실제 추천 함수에 넣으면, 권장일 `2026-08-29`인 남은 치킨을 사용한 메뉴가 “남은 치킨을 먼저 쓰기 좋아요”라고 표시된다. 권장일 경과가 식품 안전 판정은 아니므로 자동 폐기나 일괄 제외로 바꾸기보다, 경과 상태를 추천 설명에 유지하고 사용 전 확인이 필요함을 드러내는 정책과 회귀 검증이 필요하다. 기존 로직의 잔여 문제이며 이번 커밋에서 처음 생긴 점수화 결함은 아니다.
